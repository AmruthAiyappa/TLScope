Essential Cryptography and Network Security principles demonstrated by this project.

What TLS Does

Transport Layer Security (TLS) operates between the Transport layer (TCP) and Application layer (HTTP). It provides three core cryptographic guarantees:

  • Confidentiality: Encrypts payload data via symmetric stream or block ciphers (AES-GCM, ChaCha20-Poly1305) so eavesdroppers cannot inspect traffic.
  • Integrity: Detects tampering via Authenticated Encryption with Associated Data (AEAD) or Message Authentication Codes (MAC).
  • Authentication: Verifies server identity using X.509 digital certificates and asymmetric cryptography (RSA, ECDSA).
Digital Certificates & Chain of Trust

An X.509 Digital Certificate binds a public key to an entity's domain name identity, digitally signed by a Certificate Authority (CA).

  • Root CA: Pre-installed, unconditionally trusted certificates in the OS or browser trust store (self-signed).
  • Intermediate CAs: Issued by Root CAs to sign end-entity certificates, insulating the root private keys from day-to-day exposure.
  • End-Entity (Leaf) Certificate: Presented by the web server to prove its identity for specific hostnames.
Hostname Verification (RFC 6125)

Possessing a valid, trusted certificate is meaningless unless the client verifies that the certificate was issued for the specific hostname being contacted.

Under modern RFC 6125 standards, clients match the requested domain name against the Subject Alternative Name (SAN) extension. If SANs are missing or do not match, the browser terminates the connection with an identity mismatch error (even if the CA signature is completely valid).

Why Certificate Validity ≠ Total Security

A certificate can be 100% valid while the connection remains insecure. Critical security flaws can still exist:

  • The server may negotiate obsolete protocols (TLS 1.0 or 1.1) or weak non-AEAD cipher suites vulnerable to downgrade attacks.
  • The server may lack Perfect Forward Secrecy (PFS), meaning past recorded traffic could be decrypted if the server's private key leaks in the future.
  • The server may fail to implement HTTP Strict Transport Security (HSTS), leaving users open to SSL stripping attacks.
